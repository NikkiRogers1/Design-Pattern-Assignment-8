# Journal
Phase 1 - 
In Phase 1, I created an abstract VehicleReport class. Inside the class, I created a generateReport() method that controls the order of the steps. I added methods to collect data and log the status. I also declared formatReport() as an abstract method so that subclasses can provide their own formatting without changing the overall report process. The Hollywood Principle means “Don't call us, we'll call you.” In my project, the parent class, VehicleReport, controls the order of the steps and calls the methods for me. The child classes can customize their own reports without having to control the whole process. Normally, I would call each method myself and decide when it runs, but with the Template Method pattern, the parent class handles the order, and the child classes just customize the parts that are different.

Phase 2- 
When I invoked generateReport() on my TruckReport and BikeReport instances, I observed that VehicleReport was driving the execution flow because it is the parent class that controls the order of the steps. TruckReport and BikeReport are the child classes that provide their own formatting details. It was easy to understand that the parent class controls the order of the steps. It also wasn't tricky to understand why both child classes had to implement formatReport(). Since I made the method abstract in the parent class, I knew the child classes needed to provide their own details for formatting the reports.

Phase 3- 
In Phase 3, I learned that a boolean hook is optional, while an abstract method requires the child class to implement it. In Phase 1, formatReport() was abstract, so both child classes had to provide their own implementation. In Phase 3, shouldCheckMaintenance() already had a default behavior, so the child classes could choose whether to override it. I also learned that when the truck's hook returned true, it ran performMaintenanceCheck(). The bike did not run the maintenance check because it did not override the hook and inherited the default false value. This helped me understand how hooks can conditionally change the workflow without changing the overall order of the template method.


Phase 4- 
While testing my program, I had trouble remembering how to write the if statement correctly. I also had trouble understanding why BikeReport should inherit the default behavior instead of overriding the hook. I learned that an if statement checks whether the hook returns true before running the maintenance check. I also learned that BikeReport can inherit the default false value, while TruckReport overrides the hook to return true. Working through these problems helped me understand how hooks allow different subclasses to have different behaviors while the parent class still controls the overall workflow.
